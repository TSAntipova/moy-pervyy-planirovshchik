# Техническое задание. Планировщик обращений арендаторов

## 1. Назначение и границы

Планировщик ведёт журнал обращений арендаторов, показывает, кому передан вопрос, и помогает отслеживать плановые сроки ответа. Интерфейс на русском языке, основной режим использования — браузер на компьютере.

Результат реализации — три файла: `index.html`, `style.css` и `script.js`. Использовать HTML, CSS и обычный JavaScript без сборки и внешних библиотек. Страница открывается по ссылке на статическом HTTPS-хостинге. Приложение хранит данные в `localStorage`. Серверное приложение, база данных, учётные записи, история изменений, комментарии и фоновые уведомления вне объёма работы.

## 2. Кто пользуется продуктом

Продукт — индивидуальный журнал. Для просмотра чужой копии использовать отдельный профиль или сначала скачать собственный журнал. При необходимости регулярно обмениваться одним снимком коллеги могут назначить владельца исходного журнала. Скачивать копию после существенных изменений и перед заменой журнала. Очистка данных сайта или потеря профиля может уничтожить записи, внесённые после последней копии. Эти правила включить в справку.

Все коллеги имеют одинаковые возможности. Каждый браузерный профиль хранит собственный журнал для данного адреса сайта. Одна ссылка открывает интерфейс приложения. Содержимое журнала можно передать вручную через резервную копию с полной заменой данных у получателя. Поле «Кому передано» — текстовая запись. Оно не выдаёт прав и не отправляет уведомлений.

## 3. Сценарии использования

| Кто и зачем | Действия | Результат |
| --- | --- | --- |
| Коллега впервые открывает ссылку | Открывает страницу | Видит текущую неделю, пустые списки и кнопку «Новое обращение» |
| Коллега регистрирует вопрос | Заполняет карточку и сохраняет | Карточка появляется в «Все открытые» и, если назначен подходящий срок, в списках сроков |
| Коллега передаёт вопрос | Открывает карточку, заполняет «Кому передано», выбирает этап и сохраняет | Во всех списках видны новые данные |
| Коллега назначает или переносит срок | Указывает новую дату или очищает поле и сохраняет | Списки и отметки срока пересчитываются |
| Коллега планирует неделю | Листает стрелками, выбирает дату в календаре или возвращается на текущую неделю | Недельный план показывает нужные даты, текущие просрочки и ближайшие сроки сохраняют свой период |
| Коллега ищет переданный вопрос | Вводит имя получателя и при необходимости выбирает этап и приоритет | Все открытые списки показывают подходящие карточки |
| Коллега разбирает просрочку | Открывает «Просроченные» и меняет порядок при необходимости | По умолчанию видит сначала самые давние сроки |
| Коллега закрывает вопрос | Сохраняет этап «Закрыто» | Карточка переходит в архив |
| Коллега возвращается к закрытому вопросу | Находит карточку в архиве и повторно открывает её | Карточка возвращается в открытые на этапе «В работе» |
| Коллега убирает ошибочную запись | Удаляет карточку из архива и подтверждает удаление | Карточка исчезает из журнала |
| Коллега переносит журнал | Скачивает копию и открывает её через восстановление в другом профиле | После подтверждения получатель видит журнал из файла |
| Коллега защищает текущий журнал | Отменяет восстановление или выбирает ошибочный файл | Текущий журнал сохраняется |

## 4. Модель данных

Для календарных полей допустимы годы 1900–9999. Временные метки проверять по точному каноническому формату UTC с миллисекундами и календарной корректности. Будущие метки и закрытие раньше создания допускаются из-за возможной смены часов устройства. Во всех операциях использовать одну схему проверки: неизвестные поля игнорировать, пользовательские строки обрезать через trim() только по краям всего поля и измерять длину в кодовых единицах UTF-16. Внутренние пробелы и переносы сохранять.

Хранить один JSON-объект под ключом `tenant-requests-planner`. Объект содержит `schemaVersion: 1` и массив `requests`. Каждая запись содержит все перечисленные поля.

| Ключ | Поле | Формат и правила |
| --- | --- | --- |
| `id` | Идентификатор | Уникальная непустая строка, генерируется один раз при создании, сохраняется при правках и переносе |
| `tenant` | Название арендатора | Обязательная строка, 1–200 символов после обрезки пробелов |
| `description` | Описание обращения | Обязательная строка, 1–5000 символов после обрезки пробелов, сохраняет переносы строк |
| `receivedDate` | Дата поступления | Обязательная календарная дата. При создании подставляется сегодня. Допускается любая корректная дата |
| `dueDate` | Планируемый срок ответа | Календарная дата или `null`. При наличии срок должен совпадать с датой поступления или быть позже |
| `assignee` | Кому передано | Строка до 200 символов после обрезки пробелов, пустая строка допустима на любом этапе |
| `status` | Этап | `new` — «Новое», `in_progress` — «В работе», `waiting` — «Ожидает ответа», `closed` — «Закрыто» |
| `priority` | Приоритет | `high` — «Высокий», `normal` — «Обычный», `low` — «Низкий» |
| `createdAt` | Создано | Момент создания в UTC в формате ISO с миллисекундами |
| `closedAt` | Закрыто | Момент закрытия в том же формате для `closed`, `null` для остальных этапов |

Календарные даты хранить в виде `YYYY-MM-DD` и проверять с учётом длины месяца и високосного года. Показывать даты пользователю в формате `ДД.ММ.ГГГГ`. Для календарных сравнений использовать локальную дату устройства. Смена часового пояса не должна сдвигать сохранённые даты карточки.

## 5. Карточка обращения

- Кнопка «Новое обращение» доступна с любого экрана. Форма содержит все пользовательские поля. При создании этап фиксирован как «Новое», приоритет по умолчанию обычный и доступен для выбора. Срок и получатель изначально пустые.
- Нажатие на карточку открывает ту же форму с сохранёнными значениями. В открытой карточке доступны переходы между любыми открытыми этапами и закрытие, включая переход из «Новое» сразу в «Закрыто».
- «Сохранить» проверяет поля и записывает изменения. При ошибке показать сообщение у поля и сохранить введённые значения. После успешной записи закрыть форму, обновить списки и показать сообщение. Оставить текущий экран, неделю, фильтры и сортировку. Если карточка скрылась, указать, где её найти: «Все открытые» после сброса фильтров либо архив после сброса поиска. Если список опустел, показать его пустое состояние. «Отмена», закрытие окна и Escape закрывают форму. При несохранённых изменениях сначала запросить подтверждение выхода.
- При закрытии записать текущий момент в `closedAt`. В архивной карточке можно редактировать поля, кроме этапа, сохраняя дату закрытия. Действие «Открыть повторно» переводит запись в «В работе», очищает `closedAt` и сохраняет остальные ранее записанные поля. После повторного закрытия записать новую дату закрытия.
- В архивной карточке доступно «Удалить навсегда». Показать подтверждение с названием арендатора. Отмена оставляет запись в архиве. Активное обращение можно удалить после закрытия.
- В списках показывать арендатора, первые 160 кодовых точек описания с многоточием при сокращении, дату поступления, срок, получателя, этап и приоритет. В превью сохранять переносы строк. Кнопка «Открыть обращение» открывает форму с полным описанием. Для пустых полей использовать «Срок не назначен» и «Не передано». В архиве дополнительно показывать дату закрытия. Для открытых карточек показывать текстовые метки «Просрочено» и «Срок сегодня» по условиям из раздела 6.

## 6. Экраны и календарь

В верхней части страницы разместить название продукта, «Новое обращение», «Скачать копию» и «Восстановить из файла». Навигация открывает пять представлений.

| Представление | Состав |
| --- | --- |
| План на неделю | Открытые карточки с датой ответа внутри выбранной недели включительно. Семь групп с понедельника по воскресенье, включая пустые. Каждая группа подписана днём недели и датой |
| Просроченные | Открытые карточки со сроком строго раньше сегодняшнего дня |
| Ближайшие сроки | Открытые карточки со сроком от сегодняшнего дня до сегодня + 6 календарных дней включительно |
| Все открытые | Все карточки с этапом, отличным от «Закрыто», включая карточки без срока |
| Архив | Только закрытые карточки независимо от срока и выбранной недели |

При первом открытии и после перезагрузки показывать текущую неделю. Над планом вывести диапазон дат, стрелки перехода на предыдущую и следующую недели, кнопку «Текущая неделя» и поле выбора даты с календарём. Выбранная дата определяет понедельник соответствующей недели. Стрелки сдвигают начало недели на семь календарных дней. Переходы между представлениями сохраняют выбранную неделю до перезагрузки. При смене даты устройства пересчитать отметки и скользящие периоды при возвращении на вкладку и при наступлении полуночи в открытой вкладке. Явно выбранная неделя остаётся на месте. Режим текущей недели включается при загрузке и по кнопке «Текущая неделя» и следует за календарём. Переход стрелкой или выбор даты выключает режим, даже при переходе на текущую неделю.

Для пустого списка показать сообщение с его названием или смыслом. При активных фильтрах и отсутствии совпадений показать «По заданным условиям ничего не найдено» и действие сброса. Для пустого дня показать «Нет обращений».

## 7. Поиск, фильтры и сортировка

- Четыре открытых представления используют общую строку поиска и общие фильтры по этапу и приоритету. Поиск срабатывает при вводе, обрезает пробелы по краям и ищет подстроку без учёта регистра в любом из трёх полей: название арендатора, описание, «Кому передано». В пустом запросе совпадают все записи.
- Фильтр этапа предлагает «Все этапы» и три открытых этапа. Фильтр приоритета предлагает «Все приоритеты» и три уровня. Условия выбранного представления, поиска и фильтров применяются одновременно. «Сбросить фильтры» очищает поиск и оба фильтра.
- Архив использует отдельный поиск по тем же полям и собственную сортировку. При переключении экранов сохранять значения поиска, фильтров и сортировки в памяти до перезагрузки. При загрузке поиск пустой, фильтры сброшены.
- У каждого списка свой режим сортировки. Просроченные, ближайшие сроки и все открытые по умолчанию сортируются по возрастанию срока. Дополнительные варианты — срок по убыванию и приоритет от высокого к низкому. При сортировке по сроку записи без срока всегда идут последними. При сортировке по приоритету внутри уровня применяется возрастание срока с пустыми сроками в конце.
- Недельный план всегда располагает группы по датам от понедельника до воскресенья. Один переключатель для всех семи групп предлагает «Сначала добавленные» (по умолчанию) и «Сначала высокий приоритет». У карточек одного дня дата срока совпадает, поэтому сортировка по сроку применяется через порядок групп.
- В архиве варианты — «Сначала недавно закрытые» (по умолчанию) и «Сначала давно закрытые», по моменту закрытия. При любых равных ключах сортировки сравнивать момент создания по возрастанию, затем идентификатор по возрастанию.

## 8. Локальное хранение и копии

- При отсутствии ключа открыть пустой журнал. При каждом создании, изменении, закрытии, открытии, удалении или импорте формировать новый снимок, проверять его и записывать одним вызовом `localStorage.setItem`. Менять показанный журнал и подтверждать успех после успешной записи.
- Если снимок читается, но не проходит проверку, отключить редактирование и обычную выгрузку. Разрешить скачать исходную строку как TXT отдельной кнопкой «Скачать исходные данные» и восстановить валидный JSON после подтверждения.
- Если чтение недоступно, отключить редактирование, выгрузку и импорт, показать причину и кнопку «Повторить чтение». Если запись не удалась при доступном чтении, сохранить показанный журнал и черновик. Выгрузка остаётся доступной, действие можно повторить.
- Сравнивать точную строку из localStorage, включая null при отсутствии ключа. Фиксировать её при открытии формы создания или редактирования, при запуске повторного открытия или удаления и перед выбором файла для импорта. Перечитывать и сравнивать непосредственно перед записью, после всех подтверждений. При расхождении отменить запись и обновить списки. Сравнение обнаруживает только изменения, уже видимые в момент чтения. Если две вкладки успели прочитать одинаковый снимок до первой записи, поздняя запись может затереть раннюю. Для правок использовать одну вкладку.
- По событию storage перечитать журнал. При расхождении, включая удаление редактируемой карточки, сохранить черновик на экране, заблокировать сохранение и оставить поля доступными для копирования. Пользователь явно закрывает форму с подтверждением и затем открывает актуальную карточку или создаёт новую. Импорт доступен только при закрытой форме.
- «Скачать копию» выгружает весь сохранённый журнал, включая архив, без учёта выбранной недели, поиска и фильтров. Имя файла — `tenant-requests-YYYY-MM-DD.json`, дата локальная, кодировка UTF-8. Использовать тот же формат и версию схемы, что у сохранённого снимка.
- «Восстановить из файла» принимает JSON. До записи проверить, что корень — объект, версия равна 1, массив существует, все поля соответствуют разделу 4, идентификаторы уникальны, а дата закрытия согласована с этапом. Дополнительные поля игнорировать, при записи использовать только поля схемы. При неверном JSON, неизвестной версии или ошибке в записи показать причину и, где применимо, номер записи. Частичный импорт исключён.
- После проверки файла показать количество открытых и закрытых записей и сообщение «Восстановление заменит все текущие обращения». Применить замену только после нажатия «Заменить журнал». Пустой корректный снимок допустим и очищает журнал только после такого же подтверждения. После успешной замены обновить списки и показать итог, сохранив экран, неделю, поиск, фильтры и сортировку. Обмен файлами работает как перенос снимка целиком.

## 9. Интерфейс

Сверху расположены шапка и горизонтальные вкладки, затем настройки выбранного представления и карточки. Дни недели расположены в семь колонок от понедельника до воскресенья при ширине от 1200 CSS-пикселей. При меньшей ширине дни идут друг под другом. Оформление использует зелёный монохром, тонкую сетку и округлый шрифт с кириллицей. Форма открывается в модальном диалоге. Escape действует только на верхний слой и отменяет открытое подтверждение. Ошибки связаны с полями и доступны экранному диктору, сообщения о результате объявляются без переноса фокуса.

Проверять в актуальных стабильных Chrome, Edge, Firefox и Safari на поддерживаемых ими ОС. Проверочные ширины — 1280 и 360 CSS-пикселей. При 360 пикселях элементы переносятся без горизонтальной прокрутки страницы.

Контрольный журнал — 500 записей, поровну открытых и закрытых, с описаниями по 500 символов. На компьютере приёмки в Chrome поиск и открытие формы занимают до 1 секунды, чтение и проверка копии и отдельно применение импорта — до 2 секунд каждое. Время выбора файла и подтверждения исключить, устройство и браузер указать в результатах. Отклонять файлы больше 4 МиБ до чтения. Тот же предел применять к размеру сохраняемого JSON в UTF-8, чтобы выгрузку можно было восстановить. При отказе браузера записать снимок меньшего размера действуют общие правила ошибки записи.

- На компьютере управление неделей и фильтры находятся над списком. При узком окне элементы переносятся на следующие строки, карточки складываются в одну колонку. Длинный текст переносится внутри карточки.
- У полей формы видимые подписи. Кнопки-стрелки имеют доступные имена. Формы, навигация и диалоги доступны с клавиатуры, фокус видим. При закрытии диалога вернуть фокус на элемент, который его открыл, или на начало списка, если элемент исчез.
- Этап, приоритет и срочность читаются текстом. Цвет используется дополнительно. Пользовательские поля и данные из JSON выводятся как текст без интерпретации HTML.
- Напоминания реализуются списками и метками в интерфейсе. Страница не запрашивает разрешение на уведомления.

## 10. Критерии приёмки

1. По ссылке открывается пустой журнал в чистом профиле. В другом профиле данные первого профиля не видны. В том же профиле они сохраняются после перезагрузки.
2. Форма сохраняет карточку с обязательными полями и пустыми сроком и получателем. Карточка видна во «Все открытые». Строки из пробелов, невозможная дата и срок раньше поступления отклоняются.
3. Назначение срока на сегодня даёт метку «Срок сегодня» и включает карточку в ближайшие сроки. Срок на вчера попадает в просроченные. Срок через шесть дней входит в ближайшие, срок через семь дней — за их пределами.
4. Переход по стрелкам и выбор даты через календарь работают на стыке месяцев и лет. В неделе ровно семь групп, просроченные и ближайшие при листании не меняются.
5. Две карточки на один день меняют порядок при переключении на высокий приоритет, если обычная была создана раньше. Просроченные по умолчанию отсортированы от самого старого срока, переключение на убывание меняет порядок.
6. Поиск по части имени получателя работает без учёта регистра. При переключении открытого представления запрос и оба фильтра сохраняются. В архиве можно искать отдельно и менять порядок закрытия.
7. Закрытие убирает карточку из всех открытых списков. Повторное открытие возвращает её в «В работе» с прежними сроком и приоритетом. Удаление из архива требует подтверждения.
8. Копия включает открытые и закрытые карточки даже при активном фильтре. Восстановление в другом профиле воспроизводит исходные карточки. Отмена, повреждённый JSON и файл с дублирующимися ID оставляют текущий журнал без изменений.
9. Если запись в браузере не удалась, приложение показывает ошибку и не сообщает об успехе. Если другая вкладка изменила журнал после открытия формы, устаревшая форма не перезаписывает полученный снимок.
10. Строка, похожая на HTML-разметку, отображается текстом и не выполняется. К основным действиям можно перейти с клавиатуры.

11. **Разделы 4 и 6.** Проверить смену недели в полночь и после возврата на вкладку в автоматическом и ручном режимах. Смена часового пояса сохраняет даты карточек. Проверить границы лет, некорректную метку времени и эмодзи у границы длины.
12. **Разделы 5 и 7.** Проверить сообщение при создании карточки под исключающим фильтром, отмену выхода из изменённой формы, редактирование архива с сохранением closedAt, порядок при равных ключах и положение карточек без срока.
13. **Раздел 8.** Проверить скачивание исходной повреждённой строки и восстановление журнала, отказ чтения и повторное чтение. Неизвестная версия и одна невалидная карточка отклоняют весь импорт. Валидный пустой снимок очищает журнал после подтверждения.
14. **Раздел 8.** Открыть формы в двух вкладках, сохранить первую и сразу попытаться сохранить вторую после завершения первой записи. Вторая блокирует запись и сохраняет черновик, даже если событие storage ещё не обработано. Повторить с удалением редактируемой карточки.
15. **Раздел 9.** Без мыши создать и изменить карточку, отменить подтверждение и исправить ошибку. Проверить верхний слой Escape, возврат фокуса, доступность сообщений, заданные браузеры, ширины и контрольный объём.

## 11. Передача результата

Исполнитель передаёт три файла для совместного размещения. Пользователь или назначенный коллега публикует файлы на статическом HTTPS-хостинге и предоставляет ссылку. Приёмка начинается с чистого профиля и проходит по разделу 10. Краткую инструкцию по работе, выгрузке и восстановлению включить в справку интерфейса.
